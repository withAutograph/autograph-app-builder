# Builder user-facing message inventory

Date: 2026-10-22
Source: `autograph-app-builder` upstream `main` at `79e03653580221bf32174f5d651398001a6188f7`
Status: source review plus copy changes in this patch; no app session, customer conversation, generated app, provider account, or hosted environment was used. The candidate catalog and semantic reviews were captured from a working tree based at the commit below; that tree already contained in-progress edits, so neither artifact is a pristine pre-patch baseline.

This is a repository-source inventory of messages reachable through the web Builder and its public MCP session UI. It records fixed strings and the templates that this repository controls. Model-authored responses, provider-hosted sign-in pages, generated-app content, and arbitrary customer data cannot be enumerated from source; they are identified below as limits. Sanitized provider or command diagnostics remain diagnostic details so users and support can identify the concrete failure. This work changes message presentation only: the public MCP shapes, approval payloads, exact-plan digest checks, continuation/retry behavior, and authorization boundaries are unchanged.

The exact source-location catalog of fixed strings and templates is in [builder-user-facing-message-catalog-20261022.md](builder-user-facing-message-catalog-20261022.md).

A durable, machine-readable reviewed appendix is available at [builder-user-facing-message-reviewed-catalog-20261022.json](builder-user-facing-message-reviewed-catalog-20261022.json) (1.7 MiB). It classifies every one of 2,639 extracted candidate indexes: 524 primary-message fragments, 187 supporting details, 1,107 generator instructions, 567 machine-protocol values, and 254 internal strings. The counts preserve the original triage dispositions: 1,942 not-user-copy, 592 keep, 71 fixed by this patch, and 34 change recommended. All 34 recommendations are implemented in this patch and mapped in the appendix's per-row resolution fields. These counts are candidate fragments, not unique messages. The appendix also records the 325 scanned files, 29 reviewed source templates, missed message families, and limits. The candidate extraction and semantic review used a moving working checkout based at the commit above, not pristine base bytes; lexical discovery can miss indirect/localized/dynamic messages and does not prove all user-visible messages are enumerated.

Severity describes the user impact of the existing copy: **High** can obscure a material action/access/cost or recovery consequence; **Medium** can confuse the next step or expose implementation detail; **Low** is already clear or is a routine state label. Status is **Changed**, **Preserve**, or **Source limit**.

## Shared/public delivery boundary and exclusions

- The public MCP entry points are the five tools documented in `docs/public-mcp-contract.md`: `autograph_start`, `autograph_get`, `autograph_send`, `autograph_respond`, and `autograph_cancel`. They return the same event/request projection as the web session; `lib/eve/public-events.ts`, `lib/mcp/result.ts`, and `lib/mcp/session-app/` are the Builder-owned presentation boundary.
- Approval effect descriptions are authored in `lib/provisioning/hosted-operator-composition.ts` and related protected-plan producers, then projected to users by `lib/agent/approval-receipt.ts`. This patch changes only that public projector. It does not edit Arrusted, Vercel/Neon provider implementations, shared public schemas, or permission/approval checks.
- `lib/integrations/store-in-view-model.ts` and provider connection controls project connected-provider state; provider-hosted OAuth/SSO screens and error pages are controlled by those providers and cannot be inventoried from this repository.
- Arbitrary model prose, product briefs, app names, configured retention/cost descriptions, safe diagnostic detail, account/provider names, and imported API error detail are dynamic inputs. This inventory identifies their source/projection and does not assert every possible value.
- The AST/lexical discovery appendix supplements the reviewed source-location catalog but remains candidate data. All extracted indexes have a disposition; visibility can remain uncertain for some fragments, and a disposition does not establish that a candidate was shown to a user.
- Customer conversations, session payloads, generated app files, browser captures, real identities, environment secrets, provider accounts, and production/Preview artifacts were not consulted or included. Test fixtures/stories are not runtime message sources. Internal agent tools that do not emit user-visible content and server-only error strings are excluded.

## Review boundary

The paired catalog lists the reviewed fixed-message producers and templates by location; dynamic model/provider/runtime inputs remain explicit coverage boundaries. Semantic review artifacts report all indexes in their supplied UI, instruction, and server/public-producer slices, not full-repository semantic completeness. Changes in this patch are copy/rendering changes; exact authorization inputs, plan digests, retry/idempotency rules, tenant checks, event/public MCP schemas, and provider effects are unchanged. Per repository instructions, no tests, builds, broad checks, fresh installs, browser walkthroughs, or hosted proofs were run.

# Product acceptance after repository validation

The prototype-gate-repair generation preserved the requested backend outcomes in its accepted AppSpec. Its Acceptance walkthrough explicitly called for authenticated durable drafts, reload and conflict recovery, provider callbacks, a generated child preview, cancellation/retry/recovery, and tenant isolation. The exported implementation nevertheless used only client state, and its generated tests checked labels and constant arrays.

Repository compilation and test commands therefore proved technical validity, not product completion. The shared planning, apply, validation and review tool outputs now carry the accepted walkthrough with `productStatus: unassessed`. The planning output includes an implementation prompt preserving those same accepted outcomes and requiring user actions plus independent readbacks in behavioral tests. No evaluator findings are injected, no new product requirements are inferred, and code review/publication authority is unchanged.

This is a reporting and context-preservation repair, not a generic behavioral verifier. Remaining work is an application-owned executable fixture contract for synthetic identities, setup/cleanup, user actions, and independent data/job/artifact readbacks; a supported isolated runner must execute those scenarios and attach evidence before product status can become verified. Model-authored claims, test filenames, source keywords, and successful native commands must not substitute for that execution. The self-reproduction evaluator can already assess specific app outcomes separately; its evidence must remain distinct from these shared tool obligations.

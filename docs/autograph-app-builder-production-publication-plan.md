# Autograph App Builder: production publication plan

## Distribution architecture

Autograph App Builder publishes its canonical Agent Plugins package as an
immutable GitHub release in `withAutograph/autograph-app-builder`. The shared
Codex catalog lives separately in the public
[`withAutograph/marketplace`](https://github.com/withAutograph/marketplace)
repository.

The product repository is the only source of product code and release bytes.
The marketplace is an automated artifact mirror: it imports the verified Codex
package from an immutable product release and never rebuilds or hand-edits it.
This avoids coupling the organization catalog to one product while preserving
one auditable package identity.

## Canonical package release

`v0.2.6` is produced only by the protected `promote` job after every exact-main
CI lane and the exact Vercel Git Production deployment pass. The release
verification workflow then checks the published tag and assets independently.

The workflow:

1. Requires package, Agent Plugins, and Codex manifest versions to agree.
2. Requires a successful provider-owned deployment record for the exact main
   SHA and verifies health and OAuth resource metadata.
3. Builds the portable Agent Plugins archive and derived Codex marketplace
   archive once from that clean exact commit.
4. Installs and smokes the generated bytes through the Codex, VS Code, and
   Cursor harnesses.
5. Seals `promotion-receipt.json`, attests every asset, and creates the
   prerelease containing both archives, both receipts, and `SHA256SUMS`.
6. The release workflow independently verifies every uploaded digest, source
   binding, deployment binding, and provenance attestation.

Manual asset uploads are not a supported publication path.

## Marketplace import

After the immutable product release exists, run the marketplace repository's
**Import plugin release** workflow with:

- repository: `withAutograph/autograph-app-builder`
- version: `0.2.6`

The marketplace independently downloads and verifies the release, checks the
receipt and attestations, extracts only the generated Codex package, retains a
normalized import receipt, and opens a reviewed pull request. Product
repositories do not receive credentials that can write directly to marketplace
`main`.

The marketplace entry remains named `app-builder` because it must
match the immutable package manifest. The marketplace itself is named
`autograph`; the duplicated word is meaningful package identity rather than a
second copy of product branding.

## Installation

Users register the organization marketplace once:

```sh
codex plugin marketplace add withAutograph/marketplace
codex plugin add app-builder@autograph
```

Marketplace `main` is the normal upgrade channel:

```sh
codex plugin marketplace upgrade autograph
```

The marketplace publishes its own immutable catalog tags for reproducible
installation and rollback. Product and marketplace versions remain independent.

Agent Plugins-compatible clients without Codex marketplace support install the
portable archive directly from the immutable App Builder GitHub release after
verifying `SHA256SUMS` and its provenance attestations.

## Public directory

OpenAI's universal public directory is an optional additional discovery
channel, not the canonical package source. Submission requires a separate
review and publication decision. The Git-backed Autograph marketplace remains
usable without universal-directory approval.

## Acceptance

- The immutable product release binds repository, commit, tree, endpoint,
  package version, archive digests, and exactly the five `autograph_*` tools.
- The marketplace imports the published bytes without rebuilding them.
- A clean Codex profile can register `withAutograph/marketplace`, install
  `app-builder@autograph`, complete OAuth against
  `new.autograph.so`, and discover exactly five Autograph tools.
- The source checkout's loopback adapter is never an installation source.
- Neither repository contains embedded credentials.

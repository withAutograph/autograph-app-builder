# Eve 0.68.0 compatibility upgrade

Date: 2026-09-29

## Scope

Upgrade Builder from Eve 0.44.4 to the published Eve 0.68.0 release. This is a
separate compatibility change from the response-transport documentation in
[PR #568](https://github.com/withAutograph/autograph-app-builder/pull/568).
It does not depend on upstream development or a future release.

Eve 0.68.0 still sends response submissions as one `inputResponses` JSON body.
It does not expose durable response uploads or an atomic commit API. Builder
continues to require complete response batches, preserves uncertain-submission
handling, and never splits a batch automatically. Oversized resumable response
uploads remain deferred; there are no begin, append, status, or commit modes and
no Builder-only staging implementation. Bounded pending-request readback is
separate work and does not solve response submission.

## Compatibility changes

- Pin the package and lockfile to Eve 0.68.0 and update the existing local CLI
  resolver to recognize that installed release. Update AI SDK from 7.0.91 to
  7.0.105, the minimum version required by Eve's published peer dependency;
  the older SDK lacks the `experimental_evaluate` export used at runtime.
- Explicitly mount the supported `askQuestion()` tool. Eve no longer installs
  `ask_question` by default. Question responses continue to use the pending
  request's `requestId`, which can differ from its tool call ID.
- Disable the new default development extensions when launching local Eve.
  Keep prior sessions dormant on restart unless separately resumed.
- Migrate evals to explicit session handles and per-turn message results so
  multi-turn scenarios retain their conversation.
- Migrate the sandbox integration to the released environment/provider API,
  retaining Vercel Sandbox, project-scoped OIDC, supported structured commands,
  repository source setup, and `allow-all` networking.
- Read message stream version 25 and validate accepted continuation delivery
  identities. Before binding a created session, observe its durable startup
  event; an accepted candidate alone is insufficient to establish operation
  ownership during concurrent startup. Unresolved startup remains an unknown
  submission outcome.

The public MCP surface remains exactly five tools. This upgrade adds no response
transport modes and does not authorize publication, deployment, or provider
activation. Existing direct-client complete-batch behavior remains the target
contract.

## Existing sessions and rollback

The release's execution-model migration is not transparent for this project's
0.44.4 sessions. Eve's 0.57.0 release notes state that drivers started before
0.45 are inactive under the new runtime and their channel starts a fresh session.
Do not represent this upgrade as proof that old Builder sessions resume safely.

Keep the original deployment available for existing sessions. Any rollout must
account for active sessions and saved public IDs before changing traffic. Eve
also requires retaining the original deployment until imported sessions end and
retiring sessions before rolling back across the execution-model boundary.
This PR does not execute that rollout or retire user sessions.

## Local validation

- Integrated TypeScript check passes.
- Deterministic `capabilities`, `cancel-prepare-workspace`, and `accept-app-spec`
  evals pass all 119 gates against the installed runtime. These cover startup,
  preparation, multi-turn continuity, and approval/rejection boundaries.
- Focused unit checks cover local launch, stream and input projection, uncertain
  submissions, five-tool discovery, sandbox lifecycle/I/O, preview consumers,
  and the test worker environment.
- The eval worker envelope accepts Eve 0.68's explicit zero delivery-timeout
  defaults while retaining its existing authorization checks and sandbox-profile
  override.

## Evidence boundaries

Local compatibility checks and exact-head CI establish source and deterministic
fixture compatibility. They do not prove hosted provider execution, production
session migration, live-model product quality, or a new response-upload feature.
Those claims require their own evidence.

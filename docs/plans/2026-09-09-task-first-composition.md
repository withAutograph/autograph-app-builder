# Task-first composition across generated apps

## Implemented guidance

The canonical [information composition reference](../../agent/skills/design-app/references/information-composition.md) applies to new applications and revisions across domains. The primary agent instructions and design skill route to it; exported skills and generated hosted seeds include the same bytes. AGENTS.md points maintainers to the same contract.

The contract replaces component-by-component decoration with task-first information hierarchy: purpose, context, grouped evidence or input, and a clear next action. It does not mandate queues, severity groups, cards, tabs, or a universal sequence of page sections. Existing Arrusted components and supported variants remain the visual foundation. Missing reusable capability belongs in authorized shared Arrusted work, not local replacement components.

## Focused evidence

- Skill/export tests confirm the composition reference is included unchanged in both exported skills and hosted seeds, alongside the interaction reference.
- An independent instruction-level exercise produced a grouped equipment request form and a search/document-reader knowledge library. Neither copied Stock Exceptions' severity groups or replenishment layout.
- This exercise is evidence of instruction interpretation, not a rendered generation or interaction proof. It does not establish that all future apps will comply or deserve any particular design score.
- Arrusted capability inspection found existing typography, framed groups, disclosure, structured detail, form, and action APIs sufficient. Catalog discovery omissions are handled in a separate Arrusted change; no new visual component is justified by this audit alone.

## Next visual acceptance

Use these rules on the next requested preview or material revision. Preserve the actual product data, palette, and working interactions. Review whether the user can identify the task, distinguish information importance, understand related facts, and find the next action. Do not add runtime assertions, automatic judging, or another full walkthrough merely to activate this guidance.

The existing Stock Exceptions audit remains an example motivating these rules, not a universal layout or a new aesthetic ground truth. Its current screenshots and historical scores are unchanged by this instruction update.

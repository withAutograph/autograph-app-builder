# A-515 protected operator recovery acceptance

Run `mise run test:postgres-hosted-operator-recovery` to exercise the protected hosted operator HTTP handler, its PostgreSQL runtime journal, and physical resource lease. By default, the task creates a private PostgreSQL cluster, migrates it, and removes it on exit. `--database-url` accepts an explicit loopback PostgreSQL admin URL; the fixture creates and drops a unique role and database. It does not read ambient `DATABASE_URL`.

The acceptance run reports 102 named interruption cases. Each handler scenario runs in fresh child processes. Synthetic provider state and exact resource identity are stored in PostgreSQL, so a replacement process reconciles durable truth after a killed worker. The matrix covers every `resources`, `install`, `access`, and `bind` effect before and after private-state checkpoints, worker-context binding, worker-frame checkpoints, and pending-effect markers, before an effect, after a synthetic provider timeout loses the response, after receipt CAS fails before or after its durable write, and after a child is killed with durable effect state. It also covers lease claim, fence allocation, final verification, proof persistence, and lease release failures. Matching interruption points cover the `revoke`, `remove-bindings`, and `retire` cleanup effects after first preparing a grant. An `unknown` reconciliation is shown to block without assuming absence. Same-resource release replanning retains encrypted credential state and clears prior proof; a changed resource plan remains blocked until an approved cleanup completes. A separate real-PostgreSQL process proof covers competing journal CAS and resource leases, stale generations, lock release after killing the holder, and replacement recovery.

The handler matrix also calls the real protected worker `bindWorkerContext` and `recordWorkerCheckpoint` callbacks with synthetic context and receipts. Their PostgreSQL journal checkpoints are interrupted before and after durable writes, then recovered by replacement processes. This tests the callback and journal contract without executing an untrusted checkout CLI.

The fake provider only records synthetic effect receipts; it never connects to Neon, Vercel, Gateway, or a hosted deployment. Credential markers exist only in the fixture. Authenticated application behavior remains `unassessed`, and hosted Preview is `not assessed`. These checks establish local recovery behavior for the real Builder handler and PostgreSQL components, not deployed provider behavior.
